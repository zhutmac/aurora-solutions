EngageLab MA · B2B SaaS（PLG 产品驱动增长）方案

PLG 的增长本质是"让产品自己完成销售"——注册后未激活关键动作就不会付费、团队没协作起来就会流失、席位不扩张就没有净留存。 与 C 端最大的不同是：运营对象是"账户/团队"而非单个用户，触达要区分管理员与成员角色。 本方案以 Onboarding 激活、Aha 里程碑推进、团队协作扩散、试用转付费、席位扩张与增购、续费与流失预警 六大旅程切入， 统一编排 Email（主力）+ 应用内 + Web Push + App Push 四类通道。

Email（B2B 绝对主力） 应用内消息 / 引导 Web Push App Push（如有移动端）

一、为什么 PLG SaaS 必须做账户级自动化运营

激活是命门
未完成关键激活动作的账户，几乎不会转付费
账户级视角
运营对象是团队/工作区，而非单个用户
角色差异
管理员看账单与席位，成员看功能与协作
NDR 决定估值
席位扩张与增购带来的净收入留存是核心指标

注：下文所有转化率、提升幅度为 B2B SaaS 行业估算区间，落地以实测为准。本方案面向 PLG（自助注册试用）模式，销售驱动（SLG）场景需结合 CRM 另行设计。

痛点 1 · 注册了不激活

用户注册后不完成"关键激活动作"（建项目/连数据源/邀成员），产品价值没被感知，试用期白白流逝。

解法 · Onboarding 激活旅程

按已完成的 setup 步骤精准推进下一步，应用内引导 + Email 教程组合，把激活率拉起来。

痛点 2 · 单人使用、团队没扩散

只有一个人在用的账户留存极差；团队协作起来才会形成组织级依赖。

解法 · 团队协作扩散旅程

向管理员推邀请成员的价值与一键邀请；向被邀成员推首次协作引导，形成多人使用惯性。

痛点 3 · 试用到期不转化

试用结束时缺乏基于使用深度的分层引导，高价值账户与低活跃账户被一视同仁。

解法 · 试用转付费分层旅程

按账户健康度分层：高活跃直推年付方案并抄送管理员，低活跃先补激活与用例教育。

痛点 4 · 流失无预警、席位不增长

活跃度下滑到续费才发现已来不及；用量接近上限时没有及时的扩容引导，NDR 上不去。

解法 · 健康度预警 + 席位扩张

账户活跃度下滑即预警并触达（必要时转 CSM 人工）；用量达阈值即时推席位/套餐升级。

三、为什么选择 EngageLab MA

账户级 + 角色分层
  • 账户 ID 作为分群维度，管理员 / 成员差异化触达
  • 账单与席位类只发管理员，功能类发全员
Email · B2B 绝对主力
  • 企业场景邮件是标准工作通道，进箱率优化与独立 IP
  • 承载教程、报表、账单、合同类长内容
产品内行为触发
  • setup 步骤、用量阈值、协作事件秒级触发旅程
  • 应用内引导与 Email 组合，触达不打断工作流
CDP 统一身份（EUID）
  • 账户健康度、席位数、用量、订阅状态统一为属性
  • 支撑基于账户健康分的自动化预警
与 CSM / CRM 协同
  • 自动化承接长尾账户，高价值账户可转人工跟进
  • 触达记录回传，销售与客户成功共享上下文
合规 · 企业级要求
  • GDPR/CCPA、SOC 2，企业客户采购必查项
  • 数据驻留、审计留痕、RBAC 权限

五、核心旅程详细编排

旅程 1：Onboarding 激活推进

业务痛点

注册后不完成关键 setup（建项目/连数据源），产品价值没被感知，试用期白白流逝。

旅程组件配置

进入条件：事件：注册 / 创建工作区

分支：属性：已完成的 setup 步骤（精准推进下一步）

提前退出：事件：完成关键激活动作

渠道：应用内引导优先（不打断工作流），Email 补教程

预期效益

激活率 +20~35%（估算）；按已完成步骤精准推进，远优于统一欢迎序列。

旅程 2：Aha 里程碑达成引导

业务痛点

完成基础配置但没体验到核心价值（生成首份报表/跑通首个流程），仍会流失。

旅程组件配置

进入条件：属性：完成 setup 但未达 Aha 里程碑

提前退出：事件：达成里程碑

内容：用例模板、行业最佳实践、3 分钟视频演示

频控：每周 ≤2 封 Email，避免打扰工作场景

预期效益

里程碑达成 +15~30%（估算）；Aha 是 PLG 转付费的最强前置指标。

旅程 3：团队协作扩散（邀请成员）

业务痛点

只有一个人在用的账户留存极差，无法形成组织级依赖，续费风险高。

旅程组件配置

进入条件：属性：账户活跃成员数 = 1

角色分流：管理员推"邀请成员"价值与一键邀请；被邀成员推首次协作引导

提前退出：事件：账户新增活跃成员

转化统计：事件：成员接受邀请并激活，监听 14 天

预期效益

多人账户占比 +20~40%（估算）；多人协作账户的续费率显著高于单人账户。

旅程 4：试用到期转付费

业务痛点

试用结束时高价值账户与低活跃账户被一视同仁，转化效率低。

旅程组件配置

进入条件：属性：试用到期前 7 天

分支：属性：账户健康度（高活跃 / 低活跃）

角色：付费与账单类定向管理员（决策人）

递进：T-7 → T-3 → T-1，高价值账户可转 CSM 人工

预期效益

试用转付费 +20~35%（估算）；"你的团队本月已节省 X 小时"的用量数据是最强说服力。

旅程 5：席位扩张 / 套餐升级

业务痛点

用量接近上限时没有及时扩容引导，既影响体验也损失增购收入，NDR 上不去。

旅程组件配置

进入条件：事件：用量/席位达套餐阈值（如 80%）

分支：属性：超限类型（席位不足 / 用量超限）

角色：定向管理员（有采购决策权）

提前退出：事件：完成升级 / 加购席位

预期效益

NDR +5~15%（估算）；用量触顶瞬间是增购意愿最强的时刻。

旅程 6：健康度预警 + 续费保障

业务痛点

活跃度下滑到续费节点才发现已来不及，流失预警缺失是 B2B 最大隐患。

旅程组件配置

进入条件：属性：账户活跃度环比下滑 / 续费前 30 天

分支：属性：账户价值与健康度（高价值转 CSM 人工 / 长尾走自动化）

提前退出：事件：活跃度恢复 / 完成续费

协同：预警同步给 CSM/CRM，人工与自动化分工

预期效益

续费率 +8~15%（估算）；提前 30 天预警给了挽救窗口，长尾账户由自动化全覆盖。

六、渠道选型参考

B2B SaaS 渠道适配相对值（示意）：与 C 端截然不同——Email 是企业场景的标准工作通道（绝对主力），应用内引导不打断工作流，Web Push 覆盖 Web 端用户，SMS/WhatsApp 在 B2B 中使用极少（仅安全验证）。

主力通道

Email（教程、报表、账单、续费，B2B 标准工作通道）+ 应用内消息（产品内引导，转化路径最短）。

角色分层是关键

账单、席位、续费类只发管理员；功能、教程、协作类发全员。发错对象会造成困扰甚至投诉。

七、合规与安全（企业级）

企业采购必查项
  • GDPR / SOC 2 Type II 认证
  • 数据驻留与跨境传输合规
  • DPA 数据处理协议支持
数据与权限
  • 全链路 TLS、PII 脱敏、RBAC 权限
  • 账户级数据隔离，审计留痕可导出
  • 客户数据删除 / 导出接口
触达护栏
  • 营销类 CAN-SPAM 一键退订与偏好中心
  • 产品/服务类通知独立于营销退订
  • 工作时段发送、每周频控（B2B 更敏感）

八、测试计划（4 周）

周次阶段核心工作验收指标
第 1 周启动 · 数据打通确认埋点（注册、setup 步骤、Aha 里程碑、成员邀请、用量、订阅状态）；账户与角色映射事件入库率 ≥95%；账户级归属准确
第 2 周核心旅程上线J1 Onboarding + J4 试用转付费（2 条，小流量）；角色分流配置旅程触发成功率 ≥98%；角色投放零错发
第 3 周扩量 · A/BJ2 Aha 里程碑 + J3 团队扩散全量；应用内 vs Email 组合 A/B邮件打开率达标；激活率 uplift 显现
第 4 周复盘 · 扩面J5 席位扩张 + J6 健康度预警上线；与 CSM 流程对接激活/转付费/NDR uplift 可量化
