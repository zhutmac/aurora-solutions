EngageLab MA · 网约车 / 出行平台（双边）增长方案

出行平台的增长本质是"运力与需求的实时平衡"——乘客叫不到车就流失、司机接不到单就离开， 且高峰期供需失衡直接决定体验。运力调度本身就是最重要的增长运营。 本方案以双边视角切入，覆盖 乘客首单转化、通勤时段唤醒、行程履约与安全、司机上线运力调度、司机留存与收入激励、双端沉默召回 六大旅程， 统一编排 App Push（主力）+ SMS + WhatsApp + Email 四类通道。

痛点 1 · 新乘客不完成首单

补贴拉来下载，用户领了券却不叫车，或首单后不复用，获客成本被浪费。

解法 · 首单转化 + 通勤唤醒

等到通勤时段再推首单券；按个人历史用车时段与常用路线智能唤醒。

痛点 2 · 高峰运力不足

高峰期司机不在线，乘客叫不到车直接转向竞品，双边同时受损。

解法 · 司机运力调度旅程

高峰前向附近离线司机推"该区域订单激增+高峰奖励"，用数据驱动运力上线。

痛点 3 · 行程安全与履约触达缺失

司机接单、到达、行程中安全提醒不及时，既影响体验也不符合监管要求。

解法 · 行程全程强时效触达

接单/到达/行程开始结束全节点即时通知；异常（偏航、长时间停留）主动安全触达。

痛点 4 · 司机流失、乘客沉默

司机接单少收入低就转平台；乘客长期不用车即彻底流失，双边都需要主动运营。

解法 · 司机激励 + 双端召回

司机侧推收入目标与冲单奖励；乘客侧按沉默深度分层召回，双边分别运营。

五、核心旅程详细编排

旅程 1：新乘客首单转化

业务痛点

补贴拉来下载，用户领了券却不叫车，获客成本被浪费。

旅程组件配置

进入条件：事件：注册成功

提前退出：事件：完成首单

关键：等待至通勤时段再触达（而非注册即推）

内容：首单立减 + 附近可用车辆数（供给感知）

预期效益

注册→首单 +20~35%（估算）；在真正需要用车的时段推券转化最高。

旅程 2：通勤时段智能唤醒

业务痛点

全城统一时间推送无法匹配个人作息，非用车时段推送纯属打扰。

旅程组件配置

进入条件：属性：个人历史用车时段临近且当日未用车

分支：属性：时段类型（早通勤 / 晚通勤 / 夜间）

内容：常用路线一键叫车 + 当前预估价与等待时间

频控：每日 ≤2 条，用车即退出

预期效益

用车频次 +15~25%（估算）；常用路线一键叫车大幅缩短决策路径。

旅程 3：行程履约 + 安全触达

业务痛点

行程节点触达不及时影响体验；安全异常无主动触达既是风险也不符合监管。

旅程组件配置

进入条件：事件：司机接单

时间轴：接单 → 到达上车点 → 行程开始 → 行程结束评价

异常插入：偏航、长时间停留触发安全触达（Push+SMS）

分类：服务与安全类通知，不受营销退订与频控限制

预期效益

投诉率下降、安全合规达标；安全体验是出行平台信任的基石。

旅程 4：司机上线运力调度

业务痛点

高峰期司机不在线，乘客叫不到车直接转向竞品，双边同时受损。

旅程组件配置

进入条件：属性：区域订单激增 / 高峰时段前且司机离线

分支：属性：司机与热区距离（近距离直接召集 / 远距离推奖励）

内容："你附近 N 单等待接驾 + 高峰奖励 X"用数据驱动上线

提前退出：事件：司机上线接单

预期效益

高峰运力 +15~30%（估算）；运力调度是出行平台最直接的增长杠杆。

旅程 5：司机收入激励与留存

业务痛点

司机接单少、收入低就转投竞品，司机流失的重新招募成本极高。

旅程组件配置

进入条件：属性：接单量环比下滑 / 冲单任务进行中

分支：属性：司机状态（接近达标冲刺 / 长期低活跃关怀）

内容："再接 N 单得奖励 X"的明确进度激励

渠道：Push 为主，WhatsApp 承接沟通与培训（新兴市场）

预期效益

司机留存 +10~20%（估算）；明确的收入进度可视化比笼统补贴更有效。

旅程 6：双端沉默召回

业务痛点

乘客长期不用车即彻底流失；司机 7 天不上线基本已转投竞品。

旅程组件配置

进入条件：属性：乘客 14 天 / 司机 7 天未活跃

分支：属性：用户端（乘客推优惠券 / 司机推奖励与政策更新）

提前退出：事件：恢复用车 / 恢复上线

再次进入：可，间隔 15 天

预期效益

回归率 +20~40%（估算）；司机召回时效性要求更高（7 天内窗口）。

六、双边渠道选型参考

出行平台渠道适配相对值（示意）：App Push 是双端绝对主力（订单、行程、运力都是实时的），SMS 用于安全与关键节点兜底，WhatsApp 在新兴市场司机沟通中价值极高，Email 仅承载账单与结算单。

主力通道

App Push（乘客订单与行程、司机派单与运力召集，双端不可替代的实时通道）。

安全类必须兜底

行程安全类通知必须 Push 失败自动降级 SMS，确保 100% 触达——这既是体验也是监管要求。

七、合规与安全

出行安全与监管
  • 行程安全通知符合当地出行监管要求
  • 安全类通知独立于营销退订，确保送达
  • 异常行程主动触达与应急入口
位置与隐私
  • 行程与位置数据严格脱敏、最小化使用
  • 触达不泄露对方（司机/乘客）隐私信息
  • GDPR/CCPA 及当地数据法规
触达护栏
  • 营销类频控与勿扰时段（避免深夜）
  • 行程与安全类高优先级不受频控限制
  • 记录留存（如 60 天）、审计可追溯
